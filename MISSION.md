# Mission: Web Security Fundamentals

## Why
Mami is about to deploy a public portfolio. Before it goes live, he wants to
understand the real attack surface of a static site and apply baseline
protections — not just tick a checklist, but know what each measure defends
against and why it works.

## Success looks like
- Can explain what a supply chain attack is and how SRI prevents it
- Has SRI hashes on all CDN scripts in the portfolio's index.html
- Understands which HTTP security headers matter and what each one does
- Knows which protections GitHub Pages cannot provide (and what to do about it)
- Can read a browser security audit (e.g. Mozilla Observatory score) and act on it

## Constraints
- Site is fully static, deployed to GitHub Pages — no server, no backend
- Learning is grounded in the actual portfolio codebase, not toy examples
- Prefers understanding the "why" alongside the "how"

## Out of scope
- Backend security (SQL injection, auth, session management) — no server
- Penetration testing techniques
- Security for other projects (this workspace is portfolio-scoped)
